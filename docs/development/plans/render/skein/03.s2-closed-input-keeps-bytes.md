# skein 03.s2: a child's input keeps its bytes past the parent's close

A step not in the plan (ruling 181), skein 03's, in a fresh skein session:
hearth 28.4's shipped `Client` writes a hosted git's standard input whole,
then closes it, and the hosted git's first `PipeRead` answers `Count(0)`.
At skein 247ff68, `close_process_fd` (`crates/skein-sim/src/sim/processes.rs:625`)
clears the pipe's bytes at the parent's close of any spawned child's pipe
(`:638`), before `end_input` (`:639`), and `recv_bound` (`:830`) reads
that queue. simulator.md 3.2: "The simulator keeps what is the kernel's:
each child's pidfd, its pipes, its exit and its group"; a kernel pipe's
written bytes stay readable after its writer closes. The simulator's
inherited pipes already keep them: `peer_close` (`:316`), "Buffered bytes
can still be read by the process when it is the world's writer", and
`close_process_fd`'s inherited branch clears only a readable end (`:628`).

### 03.s2 A closed input keeps its bytes
Scope: simulator.md 3.2, a spawned child's pipes; the parent's close of
its write end.
Needs: nothing.
Files: `crates/skein-sim/src/sim/processes.rs`.
Shape: in `close_process_fd`'s spawned-pipe branch, clear `pipe.bytes`
only when `pipe.spec.way` is `Way::Out` (the parent's read end: nothing
reads them after); an `In` pipe keeps them, `end_input` marks it ended,
and the child reads them, then end of stream. `cut_process_descriptors`
closes through the same branch, so a cut parent's written input stays
too, as the kernel's does.
Test shape: beside `hosted_service_exchanges_three_pipes_and_settles_wait`
(`:993`), under 10 ms: `a_hosted_childs_input_closed_with_bytes_unread_reads_them_then_ends`:
the parent writes `abc` to a hosted service's `In` pipe and closes it
before the service reads; the service's `PipeRead`s answer `abc`, then
`Count(0)`. On 247ff68 the first read answers `Count(0)`.
Proof: focused, `heavy cargo nextest run -p skein-sim -E 'test(/hosted_childs_input/)'`,
the new test failing on main first and passing after; then skein's gate
through `land --gate`, the README's command as written.
Don't: change what a parent's close of an `Out` pipe does, an inherited
pipe's close, `Echo`'s exit at its input's end, or a signature.
Size: 10 production lines; the test at most 70.
