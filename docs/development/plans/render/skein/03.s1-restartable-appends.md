### 03.s1 Startup append files for a restartable process
Scope: simulator.md, 3.1 ("Files appended to") and 3.3 (a cut's restart).
Needs: nothing.
Files: `testing/skein-world/src/world.rs`; new `testing/skein-world/src/world/startup.rs`; `tests/world/tests/roots.rs`.
Shape: `World::spawn_restartable_startup(roots: Vec<StartupRoot>, appends: Vec<StartupAppend>, make: fn(&Inherited) -> P) -> usize`, as `host_startup` is to `host_roots`; `spawn_restartable(roots, make)` calls it with `Vec::new()`. `Restart` keeps the appends, checked by `check_appends`. At the spawn and at each restart after a cut, each append opens as a hosted launch's does (`open_root(&root)`, `open_append(root, &path, mode)`, `close_root(root)`) and reaches the process by `self.sim.append(pid, handle)` in `Inherited::appends`; a failure closes what opened and fails, as a root's does. The launch's opening of roots and appends (world.rs:746-787) and `restart_inherited` move to `world/startup.rs`, one opening for both, so world.rs ends at most 800 lines (850 at 7574d00).
Test shape: `tests/world/tests/roots.rs`, beside the `host_startup` tests, over `tests/world/src/roots.rs`'s machine, each under 10 ms: `a_restarted_process_appends_again_to_its_startup_file` (one append, a `Cut::Kill` before a submission; the file holds the first life's piece then the second's, whole); `a_failed_restartable_startup_append_closes_its_roots_and_fails` (its message names the append).
Proof: focused, those two tests; then `tests/world`'s suites and skein's gate through `land --gate`, the README's command as written.
Don't: change `spawn_restartable`'s signature or a user of it (skein, smith, jig, temper call it); add appends to `real.rs`.
Size: 40 production lines; the moved opening counts once, in the child (ruling 156).
